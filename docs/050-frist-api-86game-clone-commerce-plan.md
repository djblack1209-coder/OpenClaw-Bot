# Frist-API 86GameStore Clone Commerce Plan

> 最后更新: 2026-07-04
> 领域: frontend / backend / ai-pool / xianyu
> 目标: 把 Frist-API 从自研控制台收敛成类似 86GameStoreAI API 的下游售卖后台，并打通兑换码售卖、发货、兑换和渠道同步闭环。

## 一句话产品定义

Frist-API 不再只是“API 面板”，而是面向小白运营者的 **兑换码售卖与自动交付后台**：上游负责真实渠道和模型可用性，Frist-API 做下游展示、加价、发码、兑换、记录和闲鱼客服发货。

## 老板视角的成功标准

1. 老板只需要在闲鱼等平台发布商品链接和介绍。
2. 用户下单后，系统能从可售卡密池里取一张未使用兑换码发给买家。
3. 买家到 Frist-API 输入兑换码后，额度或套餐到账。
4. 后台看到卡密从“未售出”变成“已售出”，再变成“已兑换”。
5. 上游渠道状态同步到 Frist-API，用户看到的是下游可售模型和通道状态。
6. 所有上游倍率统一加价 0.1，例如 Plus 从 0.18 展示/售卖为 0.28。

## 第一阶段边界

### 本轮要落地

- UI：改成浅色 86GameStore 风格后台骨架，保留 Frist-API 的 CC Switch、兑换、API Key、模型、记录等功能入口。
- 兑换：补齐管理端卡密列表摘要、状态分组、导出文案、用户端兑换成功反馈和记录可见性。
- 渠道同步：新增可配置的“上游倍率 +0.1”转换函数和管理端同步摘要，先支持本地数据/未来上游 API 接入。
- 闲鱼自动发货：新增 Frist-API 侧履约队列和脚本接口，先能根据订单信息分配未售出卡密、生成发货话术、标记已发货；真实闲鱼登录态后再接自动检测。

### 本轮不直接做的高风险动作

- 不复制 86GameStore 私有源码、Logo、密钥或登录后接口返回。
- 不绕过闲鱼风控，不做刷量、批量私信陌生人、诱导违规交易。
- 不在没有老板授权登录态的情况下读取闲鱼真实订单。
- 不把 Plus 自用账号池直接卖成用户路由库存。

## 核心模块设计

### 1. UI 克隆骨架

- 视觉方向：浅色背景、白色卡片、青绿色主色、左侧导航、顶部账户区、表格/表单优先。
- 用户端导航：仪表盘、API Key、使用记录、可用渠道、CC Switch、兑换码、套餐订阅、个人资料。
- 管理端导航：概览、价格倍率、兑换卡密、人工入账、渠道库存、闲鱼发货、Plus/RT 台账、生产检查、审计。

### 2. 兑换码全链路

卡密状态机：

```text
unused 未售出 -> sold 已售出/待兑换 -> redeemed 已兑换 -> disabled 已停用
```

兼容旧数据：历史只有 `unused/redeemed/disabled` 的卡密继续可用；新增 `sold` 不影响旧兑换逻辑。

### 3. 上游渠道同步与倍率

- 上游倍率字段统一进入 `costMultiplier`。
- 下游倍率 = 上游倍率 + `FRIST_API_RATE_MARKUP`，默认 `0.1`。
- 如果上游没有倍率，按原 Frist-API 模型价格兜底。
- 渠道状态只展示脱敏字段：模型、平台、健康状态、延迟、倍率、更新时间，不展示上游 Key。

### 4. 闲鱼自动发货

Frist-API 先提供平台无关的履约接口：

```text
订单信息 + 商品套餐 -> 分配卡密 -> 生成发货消息 -> 记录 sold -> 等待用户兑换 -> redeemed 后提醒确认收货
```

后续接闲鱼真实检测时，只需要把闲鱼订单转换成同一个履约接口，不改兑换核心。

## 验收方式

- `apps/frist-api` 全量 Node 测试通过。
- 浏览器截图包含浅色 86GameStore 风格用户端和管理端。
- 管理端可以生成卡密、查看状态、复制发货文案。
- 用户端可以兑换卡密，余额到账，记录可见。
- 渠道倍率转换测试覆盖 `0.18 -> 0.28`。
- 闲鱼履约测试覆盖“订单进来 -> 分配卡密 -> 生成消息 -> 标记 sold”。
