# JIYU AI 生产品牌与运营边界

> 最后更新: 2026-08-09
> 领域: `frontend` / `backend` / `deploy` / `security` / `xianyu`

## 目标

JIYU AI 是唯一用户可见品牌，生产入口为 `https://jiyu.245334.xyz/`。用户端只展示 JIYU AI、JY 图形 Logo、渠道A和渠道B；上游厂商名称只保留在管理侧的内部路由标识，不出现在用户文案中。

## 当前生产事实

- Oracle ARM 运行官方 Sub2API `v0.1.172` 的 JIYU 构建，服务绑定 loopback；PostgreSQL 和专用 Redis 独立运行。
- Cloudflare 代理、WAF、DDoS 缓解、注册/登录边缘限流和站内内容预拦截已启用。
- 6 个文本渠道和 2 个生图渠道按渠道A后渠道B分段展示；监控周期 300 秒，抖动 ±30 秒，状态必须反映真实上游结果。
- 文本和生图业务分组采用由资产所有者控制的上游定价策略；展示价格与监控状态必须反映当前批准的运营配置。
- Claude 端点和 ChatGPT 端点在创建 API 密钥页分开说明；创建后可直接导入 CC Switch，并默认开启用量查询和本地路由转发。
- 充值中心嵌入链动小铺页面；支付回调未建立前，不把外部商品页伪装成本地余额到账。

## 运维入口

```bash
make sub2api-check
make jiyu-sub2-replenish
make jiyu-sub2-replenish-dry-run
```

WebUI 更新必须由受管更新代理下载、校验 SHA-256、暂存并在服务重启后核对版本；浏览器不得传入任意命令或下载地址。

## 当前边界

- 真实支付商户、链动小铺可信回调、邮箱/社交登录供应商凭据、S3/R2 对象存储和第三方上游恢复仍由资产所有者提供；缺少凭据时保持关闭或只读。
- 闲鱼自动发货保留各自授权入口；自营号池补号 GUI 是唯一材料处理入口，Telegram 不承载凭据也不控制批次。
- 上游 401/429/5xx 直接显示为异常或降级，不用静态绿色掩盖。

## 验收

每次生产变更至少执行 `make docs-check`、对应 Python 聚焦回归和 `git diff --check`；用户可见 UI 变更需保存前后截图，任何密钥、Cookie、验证码和订单凭据不得进入截图、日志或文档。
