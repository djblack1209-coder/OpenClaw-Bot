# OpenEverything 使用手册（给老板）

> 最后更新：2026-08-09
> 目标：老板只看绿灯/黄灯/红灯，不记技术命令。

## 每天早上第一件事

1. 打开：`http://127.0.0.1:18800/dashboard`
2. 看首屏颜色：
   - 🟢 绿灯：不用管，系统在自动看守。
   - 🟡 黄灯：按页面里的“下一步”做。
   - 🔴 红灯：按页面里的“下一步”做；仍不能恢复时联系技术支持。
3. 如果页面打不开，再运行：

```bash
cd ~/Desktop/OpenEverything && scripts/auto_recovery.sh --dry-run
```

老板只运行 `--dry-run` 预演，不要自行去掉它。任何会重启服务的恢复动作，必须由技术支持先读取最新运行状态、确认可恢复备份和最小影响范围后执行。

## 闲鱼有新订单怎么办

正常情况：你什么都不用做。

- 买家付款后，系统自动发卡密。
- 浏览器助手看到“已付款/待发货”后，才会点发货。
- 买家兑换后，系统会继续观察是否创建 API、导入 CC Switch、调用模型。

如果看到“补救队列不为空”：

1. 打开 `http://127.0.0.1:18800/dashboard`
2. 展开“补救队列”
3. 按页面提示复制话术或让浏览器助手重试

如果操作台提示卖家会话断开：打开 OpenClaw 桌面端闲鱼页面，点击“启动并打开运营台”即可启动隔离卖家窗口；再由你本人在该窗口登录闲鱼并保持窗口打开。不要导出、复制、粘贴或转发 Cookie/Token，尤其不要发送到聊天、文档、脚本参数或截图。若按钮提示找不到本机启动器或 Node.js，属于当前安装包的本机运行文件未发现，不要改用剪贴板或聊天传递凭据。

## 没有真实小额订单时怎么办

不要用模拟结果代替业务结论。日常只看真实健康探针和实际订单状态；首次或恢复售卖前，必须以一笔新的真实小额订单完成付款、自动发货、站内兑换和 API 调用为准。

“替换模式模拟验收”只供技术支持排查某个环节是否能演练，不能用于日常验收、放量或替代真实买家。技术支持明确要求时，才按其步骤打开该区块并提供结果；不要自行补齐模拟步骤或据此修改商品、库存、账号或支付设置。

## 系统红灯怎么办

### 1. 先跑一键健康检查

```bash
cd ~/Desktop/OpenEverything && scripts/auto_health_check.sh
```

看每一行后面的“怎么办”。

### 2. 仍然红灯，再跑一键恢复预演

```bash
cd ~/Desktop/OpenEverything && scripts/auto_recovery.sh --dry-run
```

老板不要自行执行实际恢复。任何带 `--confirm` 或会重启服务的恢复动作，都由技术支持在取得最新状态、确认可恢复备份和最小影响范围后执行。

### 3. 仅在技术支持要求时导出诊断状态

打开：`http://127.0.0.1:18800/export-status`

把页面里的 JSON 发给技术支持。它用于定位问题，不能证明业务已恢复；业务恢复仍以真实健康探针和真实订单链路为准。报告不得转发给无关人员。

## 备份和恢复

### 手动备份一次

```bash
cd ~/Desktop/OpenEverything && scripts/local_backup.sh
```

默认备份到 iCloud（如果可用）或桌面 `OpenEverything-backups`，保留 30 天。

### 恢复前先预演

```bash
cd ~/Desktop/OpenEverything && scripts/disaster_recovery.sh --dry-run
```

真正恢复会覆盖数据，老板只做预演；任何带 `--confirm` 的动作都必须由技术支持在确认最新状态、可恢复备份和最小影响范围后执行。

## 老板只需要记住一句话

平时只打开：`http://127.0.0.1:18800/dashboard`

看不懂就联系技术支持；对方需要诊断信息时会让你导出状态报告。
