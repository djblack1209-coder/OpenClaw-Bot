# GitHub 展示与求职项目评审

评审日期：2026-09-13。目标岗位：AI 应用 / 全栈工程师。

本轮范围是公开展示、外部读者的首次体验、关键工程实现抽查与对应完善，不是全仓安全审计或生产运行验收。运行事实继续由[当前基线](current/current-baseline.md)维护。

## 判断

项目有可供深入讨论的工程内容，但原有首页没有把它们转化为清晰的阅读路径。更有价值的定位是“可追踪的个人 AI 自动化”：把交互、编排、预算和投递状态连接起来。展示不应以集成库数量、Bot 数量或未经验证的自主能力作为主要卖点。

## 发现与本次处理

| 发现 | 依据与影响 | 本次处理 |
|---|---|---|
| 项目名称与上游关系不够清楚 | 原首页使用 OpenClaw Bot，本地项目名为 OpenEverything；外部读者难以区分独立集成与上游原创能力 | 首页统一以 OpenEverything 展示，保留仓库名并说明上游边界 |
| 首页偏向内部运维交接 | 生产节点、备份历史先于可运行示例，读者难以快速理解价值 | 首页改为价值、视觉预览、零密钥体验、三个工程切面和源码入口 |
| 架构文档包含旧规划 | 原 `004-architecture.md` 混合 OMEGA 草案、旧 Stars 数、规划中的能力与已退役模块 | 改为当前调用边界、三项设计取舍与实现链接，旧设计保留在 Git 历史 |
| 新人需要较重环境才能开始 | 原快速开始首先指向整套隔离安装检查 | 新增独立静态讲解页，Python 标准库即可预览，全部使用合成数据 |

| GitHub 文档入口失效 | Issue 模板指向已删除的 `docs/003-docs-index.md` | 指向首页文档导航，增加公开入口链接检查并接入 `make docs-check` |

| 缺少英文入口 | 原首页为中文 | 增加英文介绍，明确深入文档与演示当前使用中文 |

## 值得保留的技术亮点

1. **模型调用状态与预算。** [cost_ledger.py](../packages/clawbot/src/core/cost_ledger.py) 采用 SQLite 写事务做预算预留，区分预留、已发送、已结算和未知状态；[cost_policy.py](../packages/clawbot/src/core/cost_policy.py) 依赖显式价格配置。适合讲并发、幂等、失败语义和成本边界。
2. **调度持久化与时区。** [scheduled_cycle.py](../packages/clawbot/src/intel/scheduled_cycle.py) 有文件锁、业务日期认领与副作用前落盘，测试包含进程退出及 DST。适合讲“避免重复执行”与“严格 exactly-once”的区别。
3. **完整应用连接。** React/Tauri、Python/FastAPI 与 Telegram 提供前后端及原生边界的讨论空间；首次配置区分保存与运行验证，适合讲真实用户路径与错误恢复。

## 与成熟方案的关系

以下是根据官方项目定位做出的选型判断，并非性能排名；未进行这几款产品的横向实测。

| 方案 | 官方项目定位 | 本项目的合理边界 |
|---|---|---|
| [OpenClaw](https://github.com/openclaw/openclaw) | 运行在用户设备上、连接多种交互渠道的 AI 助手 | 复用其运行时，清楚说明集成层与本仓库工作；避免暗示是上游官方发行版 |
| [Dify](https://github.com/langgenius/dify) | 面向 LLM 应用的工作流、RAG 与模型工具平台 | 需要通用可视化 LLM 工作流时先评估成熟产品；本项目聚焦个人本机控制和具体状态管理 |
| [n8n](https://github.com/n8n-io/n8n) | 支持可视化与代码的自动化工作流平台 | 常规 SaaS 连接无需重复建设；本项目的学习价值在原生控制、费用状态和调度失败语义 |

自建的价值在于你能解释需求、修改实现、验证失败路径并承担维护成本。扩大集成数量之前，优先让一条高频业务路径稳定、易安装、可演示。

## 后续优先级与验收标准

| 优先级 | 工作 | 完成标准 |
|---|---|---|
| P1：展示可信度 | 录制真实 Tauri 应用的短演示，使用专用演示配置 | 从打开应用、触发任务到看到结果的连续录屏；注明合成内容与真实服务边界；无私有信息 |
| P1：体验门槛 | 将静态讲解页发布为可点击预览 | 仅发布 `apps/project-showcase/`，外部访客无需克隆即可操作；页面与仓库源码对应同一版本 |
| P1：个人贡献 | 整理可核验的代表性提交 | 每个简历亮点都有明确本人参与范围、提交、实现、回归证据和取舍 |
| P2：安装可靠性 | 缩小最小运行依赖，完善首次配置验收 | 新机器按文档安装，完成一条真实只读业务路径，不依赖维护者本机状态 |
| P2：许可证与归属 | 核对 root、桌面包与 vendor 的许可证及作者声明 | 明确分发范围与第三方声明；当前 root Apache-2.0、桌面 package.json MIT / OpenClaw Team 的差异不能擅自改写 |
| P2：运行可靠性 | 补齐自然调度回执和恢复证据 | 实际业务窗口内投递、重复触发、失败恢复均有可核验记录 |
| P3：商业化 | 收敛单一用户场景，验证是否有人持续使用 | 先取得真实使用反馈，再考虑多用户隔离、支持、计费和可靠性目标 |

## Star 与分享方式

Star 数无法由 README 改版保证。可执行的策略是让陌生开发者更容易理解和尝试，并围绕真实价值分享：

- 分享一个具体工程问题，例如“模型请求超时后如何避免预算超支”，配合短演示和实现链接。
- 邀请读者复现、提问题或贡献失败场景；不购买 Star，不批量私信或发布垃圾内容。
- 根据真实 Issue 收敛改进方向，而不是为列表热度堆功能。
- 面试分享从[工程导览](017-engineering-tour.md)出发，讲清一个失败路径和一次设计取舍。

仓库 About 建议文案：

> OpenEverything — Personal AI automation with Telegram, a Tauri console, and traceable model budgets. Python/FastAPI + React/Rust.

建议主题在现有标签基础上突出 `ai-agents`、`automation`、`fastapi`、`llm-routing`、`telegram-bot`、`tauri`、`react`、`python`、`typescript`。发布讲解页后再填写有效的 Homepage 地址，不使用尚不存在的链接。

## 本轮验证与限制

- 现有关键行为回归：费用账本与情报调度两个 Python 测试文件通过；引导与新闻入口的 43 项 Node 检查通过。
- 文档门禁：14 项 Node 检查通过，公开入口的本地链接存在性检查通过；它不负责验证所有外链或 Markdown 锚点。
- 浏览器实际检查：桌面总览、手机窄屏无横向溢出；调度重复认领、夏冬时换算、窗口外跳过；预算超时敞口、拒绝、结算和重置。
- 截图直接来自新增讲解页，使用合成数据。讲解页通过 CSP 禁止业务网络连接，无第三方脚本或外部字体依赖。
- 本轮没有修改业务后端、桌面应用或依赖锁，也没有启动 Gateway / ClawBot、发送真实消息、调用收费模型或部署独立服务。
- 真实 Tauri 新录屏、线上讲解页发布、第三方账单对账、跨平台安装与自然投递仍需各自完成验收。

GitHub 合并和发布状态以实际 PR、默认分支与部署结果为准；本报告不将本地修改视为公开首页已经更新。
