# JIYU AI 当前生产基线

> 更新时间：2026-08-11（Asia/Singapore）。生产运行时是唯一事实；本仓库只用于维护、恢复和异地备份。历史注册表中的 Frist/CC 描述不构成当前生产架构；闲鱼当前状态以本文件为准。

## 范围与约束

- 本轮只复查本机 Mac OpenClaw/ClawBot 与 Oracle Singapore JIYU/Sub2API。腾讯旧备机、中国 origin 和其他项目只做边界确认，没有修改。
- 按用户本轮明确授权只执行了两次最低成本异步生图链路探针和一次中央 MCP 端到端探针；任务均在上游失败、没有图片成功、没有扣费。没有制造订单、支付、Telegram 外发或压力负载，也没有调用会改变使用时间的 `/v1/usage`。
- 真实设备覆盖本机签名 App 与现有 Chrome。当前没有实体手机，因此移动端明确未验证。
- 本轮新增写入均有 prestate、备份和回读：建立 JIYU 专用私有 R2 bucket 与受限 token，保存 Sub2API 原生备份/异步生图存储与定时备份配置，创建限额中央生图 Key 和 1 USD 内部运维额度，安装中央 MCP。闲鱼侧发布并核对 1/10/30/50/100/300/500/1000 元八档商品，每档仅 1 个；8 个商品均映射到 Sub2API 原子领码适配器，并开启首单成功后自动暂停的观察票。没有制造订单或发送测试消息。

## 3. 未修复问题及原因

- OpenClaw Gateway 当前健康，但服务定义由 `2026.6.11` 安装，CLI/运行时为 `2026.7.1-2`。原生审计级别仅为 recommended，未出现启动、RPC 或健康失败；本轮不为消除提示而强制重装和重启。维护窗口内可先备份 plist，再执行原生重装与回读。
- GitHub 仍提示 1 个中等级别 Rust 依赖告警，本地 `cargo audit` 对应 GTK3/`glib 0.18` 兼容链及上游未维护警告。现有 Tauri/Wry 链没有可安全单包替换的 GTK4 路径；强升或手改锁文件会制造桌面回归，因此等待上游成套迁移后再复查。
- 桌面端与 LaunchAgent 模板仍有本机绝对路径 fallback。当前机器启动正常，且管理器已支持 `OPENCLAW_PROJECT_DIR`；跨机器或移动目录前没有真实收益，不做猜测性重构。
- 闲鱼八档商品已上架、映射并进入首单观察。尚未发生这组新商品的首笔真实购买，因此不能宣称新商品的支付、发码、买家兑换和确认收货已经通过；系统会在首笔真实发卡成功后自动暂停，届时只需回读同一订单的预留、消息和兑换状态，不得用合成订单替代。
- Frist-API 是当前仍在运行的旧技术名，而不是 Sub2API 官方组件或第二库存。它已经不再持有旧 `runtime.json` 卡池，但仍增加一项 Node 服务维护面；Sub2API 官方尚未提供外部订单幂等、按面额原子领取兑换码的 API，因此不能在没有等价能力时直接删除。CC 中转是本机闲鱼助手的历史命名；其不可替代职责是接收平台付款信号和向买家发送一次性消息，不是 JIYU 的账户、余额或库存系统。
- 闲鱼开放平台的小程序/虚拟订单能力目前不公开自助申请，只接受闲鱼运营定向邀请的服务商；未经邀请的注册不会通过。申请表本身已准备到只缺企业淘宝昵称，但现有个人卖家登录态不能直接升级为该官方链路，也不能在当前网页版把八档安全合并为一个原生多规格商品；在同主体企业账号、合同、C/B AppKey、聚石塔、奇门审批和发布材料完成前，当前八个独立商品加卖家桥接仍是唯一已验证路径。淘宝企业入驻页受浏览器安全策略限制，必须由用户在 Chrome 手工完成登录、实名和授权。
- `packages/clawbot/relative-launch/` 是 gitignored 的评审产物且没有生产调用者，但无法从 Git 恢复；按照“只删除可由 Git 恢复内容”的约束，本轮没有删除。运行数据、浏览器 profile、`.openclaw`、备份、迁移、支付和关键浏览器测试同样保留。
- 实体手机未连接，移动端布局、登录和业务流程未验证，不宣称通过。
- 中国 origin、域名/ICP、独立健康端点和回滚包均未具备；Cloudflare China Network 还需要 Enterprise、单独订阅和合规审核。本轮禁止新增费用和修改共享中国主机。
- 离机 GPG 公钥和真正独立的备份介质仍由资产所有者提供；没有这些条件时，现有 `--require-offsite` 应继续失败关闭。

## 4. 仍值得实施的优化

### P0

- **观察首笔自然订单**：八档商品、映射和首单观察已就绪，无需再操作。下一笔真实已付款订单最多发送 1 条兑换码并自动暂停；随后回读同一订单的 Sub2API 预留、闲鱼消息和买家兑换状态。收益是用真实业务关闭新商品履约证据缺口；开发成本为 0，日常维护仅在首单后检查约 5-10 分钟。
- **恢复至少一条生图上游**：渠道 A 需供应商修复 403 权限，渠道 B 需提供明确支持 `gpt-image-2` 的账户/分组。收益是让已经就绪的异步 API、R2 和中央 MCP 真正返回图片；平台侧维护成本为 0，供应商账户处理约 10-30 分钟。恢复后只做一次低质量单图验收，再启用监控。

### P1

- **退役 Frist 兼容适配器（条件满足后）**：仅当 Sub2API 上游提供等价的外部订单幂等领码接口，或其现有 API 能在不扩大管理员凭据、不复制库存的条件下提供同等语义时执行。收益是减少 1 个 Node 服务、1 个数据库角色和 1 个部署入口；当前缺少上游能力，强行替换会增加而非降低维护成本。
- **Gateway 服务定义收敛**：只在维护窗口执行。收益是消除一次版本安装漂移并降低下一次 CLI 升级后的启动差异；预计停机为一次本机服务重载，持续维护成本接近 0。当前健康，立即执行的用户收益为 0，所以暂缓。
- **路径 fallback 收敛**：先让桌面端、启动器和 plist 全部优先使用已有 `OPENCLAW_PROJECT_DIR`，仅在确有跨目录安装需求时删除绝对路径。收益是移动工作区后减少 1 类启动回归；实现约半天，后续维护低，当前机器收益有限。
- **卖家桥接首单回读**：下一笔自然订单成功后确认观察票已消费、自动发货已暂停且没有重复消息。收益是关闭新八档的重复外发风险；开发维护成本为 0，禁止用合成消息替代。
- **闲鱼官方虚拟订单接入（获邀后）**：用官方订单消息、订单查询和逐单虚拟发货替换浏览器 Cookie/验证码/点发货环节，继续复用 Sub2API 原子预留、卡密兑换和账本，不新建库存。收益是减少 3 类浏览器脆弱点；一次实施预计 2-4 周，持续增加聚石塔、授权续期、客服和发布审核维护。在获得运营邀请和合同前不开发空壳适配器。
- **离机加密备份落地**：用户提供 GPG 公钥和独立介质后复用现有 `local_backup.sh`，不新增备份组件。收益是本机全盘故障时仍可恢复；一次配置约 30 分钟，每月恢复抽检约 10 分钟。
- **原生备份月度恢复抽检**：R2 已配置，不再新增备份组件。每月从原生备份恢复到临时数据库并立即清理；约 10 分钟/月，可持续验证异地副本可用。

### P2

- **Turnstile**：只有出现可量化的自动注册或邮箱额度消耗时再启用。可能降低滥用，但会增加挑战失败和客服成本；没有真实误伤/攻击数据前不做。
- **中国双站分流**：需中国 origin、域名/ICP、合规和付费方案先成立。收益是大陆访问路径缩短，维护成本至少增加一个故障域、健康探针和回滚面；当前前置不成立。
- **语义审核**：只有供应商提供免费、专用安全分类模型时才复用原生 Prompt Audit。当前用普通聊天模型替代会增加费用、误判和明文提示词风险。
- **移动端实机**：连接实体手机后复用现有关键浏览器流程验收，不建立一次性测试包。
- **异步图片成功对象抽检**：功能已启用，等上游权限恢复后验证一次成功对象、MIME、20 MiB 限制和 2 天生命周期；不增加周期性付费探针。
- **桌面 GTK4 上游迁移**：仅在 Tauri/Wry 官方兼容链完成迁移后评估。收益是关闭现有 RustSec 警告；当前自行分叉的维护和回归成本明显高于收益。

## 5. 已无继续优化价值

- 不为版本号强制升级 OpenClaw、Sub2API/New-API、glib、Wry 或 Tao；实际 OpenClaw 已是官方稳定版，生产 Sub2API 已基于当前受管上游版本且健康。
- 不新增 Gate、证据编译器、计划 Schema、常驻 AI 管理面、第二事实源、第二补号入口、合成压力测试或周期性计费模型探针。
- 不用原生 OpenClaw 备份替换覆盖范围更完整的现有备份；也不并行叠加第三套备份工具。
- 不把“异步生图对象存储”误当成 MCP 服务。原生异步 API 的客户端可直接使用；需要工具发现的 Claude/Codex/OpenCode 继续复用中央维护的单个 MCP，用户不再自行封装。
