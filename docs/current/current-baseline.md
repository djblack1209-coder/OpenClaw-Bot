# JIYU AI 当前生产基线

> 更新时间：2026-08-12（Asia/Singapore）。生产运行时是唯一事实；仓库只用于维护、恢复和异地备份。`docs/current/` 只保留本文件。

## 范围与结论

- 范围仅限本机 Mac OpenClaw/ClawBot 与 Oracle Singapore JIYU/Sub2API；中国 origin、腾讯旧备机和其他项目未修改。
- 用户已确认闲鱼商品全部下架且没有待处理订单。闲鱼客服、卖家桥、自动交付和 Oracle Frist-API 已安全退役，不再是恢复目标。
- 中央生图 MCP 已退役。支持原生异步图片 API 的客户端直接调用 Sub2API；普通文本客户端和 CC Switch 不再注入隐藏生图工具。
- 没有制造模型请求、订单、支付、Telegram 外发或压力负载。没有实体手机，移动端不宣称通过。
- 本轮生产收口完成：上游账号是 V1 渠道监控的运行时凭证来源，费率同步保持现有安全边界；active 文本渠道不再公开生图模型，未验证生图渠道保持禁用。

- 完整删除闲鱼专属后端、Bot 命令、API/RPC、控制台、CookieCloud、卖家桥、自动发货、扩展域名、提示词、静态资源、启动脚本和对应测试；支付、订单、授权、数据库迁移和历史数据保留。
- 在最新 prestate 与回滚备份后，卸载本机 2 个闲鱼 LaunchAgent，删除对应 plist 和日志轮转；端口、进程、核心健康均完成回读。
- 在 Oracle 一致性备份与独立 Frist 归档后，删除 Frist service/timer/运行时和管理器部署命令，关闭 3180，并禁止旧数据库角色登录；Sub2API 业务探针保持 200/401。
- 删除中央生图 MCP 的 CC Switch 注入、安装器、服务源码、锁文件和专用教程；保留通用 MCP 插件商店，不把两者混同。
- OpenClaw App、API、i18n、首页、设置、Money、Social 和 Bots 页面同步移除闲鱼控件；真实 App 只展示 5 个仍有产品意义的受管服务。
- 删除无调用的 `start_all.sh`、`stop_all.sh`、旧健康脚本、卖家脚本和硬编码浏览器 bootstrap plist；严格健康脚本也删除了已退役 18800 控制台与 CC 中转巡检，避免为不存在的业务报错。
- 修复上游切组后的监控漂移：V1 monitor 每次探测优先从现有 channel/group/account 关系读取当前 `base_url` 和 API key，找不到绑定时才回退旧快照；凭证只在进程内使用，不写日志或仓库。现有费率同步开关已在 10 个文本账号启用，下一次成功探测才会按既有 CAS/范围保护更新账号费率与 group `+0.05` 合同，不会因手动切组立即盲改价格。
- 回滚检查不再强制把本机 app-only 发布绑定到 DMG；有 DMG 时仍强制校验 SHA-256，任何回滚仍强制校验当前/上一版签名、CDHash 与源码补丁哈希。
- 文档从重复注册表、发布证据和阶段报告收敛为 28 份，`docs/current/` 只有本基线。共删除 62 个 tracked 文件、2,553,733 bytes；增加 530 行、删除 40,968 行，净减少 40,438 行。

## 3. 未修复问题及原因

- 两条生图上游仍分别受权限拒绝和目标模型缺失阻断。Sub2API、Redis、鉴权和 R2 路径可用，但不继续制造付费探针，也不恢复中央 MCP 掩盖上游失败。
- Huyun 没有可用的 `/monitor` 页面，不能把供应商后台的上游分组变化当作本站事实；本站只会在下一次 V1 成功探测且通过现有费率保护时同步。新增渠道仍需在 Channels/Groups/Accounts 建立绑定，不能只填一个 Key+地址就绕过分组、价格和区域策略。
- B OpenAI Pro 最近真实 V1 探测出现间歇性慢响应（约 14-20 秒）并显示 `degraded`，前后仍有 `operational`；它不是本次发布引入的错误。当前先保留渠道与已有用户访问，等待上游稳定或真实用户探针持续复现后再决定降级/停用，不制造额外请求。
- App 只有内部 ad-hoc 签名。正式 DMG bundle 在系统打包脚本阶段失败且事务脚本未替换现有 App；本机 app-only 运行与回滚不受影响。对外分发仍需 Apple Developer ID、公证材料和单独发布验收。
- Chrome 安全策略不允许自动访问 `chrome://extensions`；已有真实浏览器冒烟通过，但当前扩展管理页未人工确认。
- 插件商店中的 GitHub、Brave Search、Google Maps 三个通用 MCP 包已被 npm 标记 deprecated，但仍有 App 受管目录调用者且没有已知漏洞；现在删除会直接损失产品能力，等待成熟替代品后做替换删除。
- RustSec 仍报告 Tauri 跨平台 GTK3/`glib 0.18` 维护或 unsound 告警。macOS 实际构建与运行通过，不做无上游迁移路径的单包升级。
- 支付/授权后端保留一个当前未监听的 18800 默认合同；它属于被明确要求保留的支付和订单能力。只有正式启用支付时才统一参数化，当前迁移没有收益。
- 实体手机未连接，移动端未验证。最终本机备份恢复演练通过，但加密离机目录未配置；独立离机介质、MFA 和账户恢复仍需资产所有者处理。

## 4. 仍值得实施的优化

### P0

- 当前没有生产阻断。不要为清零告警恢复闲鱼/Frist/中央 MCP，也不要修改健康的 DNS、路由、数据库或核心服务。

### P1

- **稳定性：上游生图恢复后的单次验收。** 供应商确认权限和模型后只做 1 次最低成本单图，验证终态、MIME、对象大小、访问期限和 R2 清理。收益：把当前不可用能力转为可交付；成本 5-10 分钟加一次实际调用费用，之后不保留周期探针。
- **安全性/维护成本：替换 3 个 deprecated 通用 MCP 包。** 只有找到受维护、权限边界相同的 drop-in 轮子时才替换并删除旧包。收益：减少 3 个停止维护的直接依赖和 CI 警告；实施约 0.5-1 天，当前无漏洞时不抢跑。
- **用户体验：实体手机验收关键页面。** 连接真机后复用现有关键浏览器流程检查登录、设置和 JIYU 使用，不新建一次性测试包。收益：补齐唯一设备盲区；成本约 15-30 分钟。
- **维护成本：按完整产品域退役，而非按文件数删。** 只有用户明确停用交易、Intel、社媒等完整域并确认一个自然周期无生产调用后，才连同 UI、后端和测试一起删除。每退役一个域预计减少 300-1,700 行页面代码及对应后端，实施约 0.5 天；没有停用决策时收益为负。
- **稳定性/维护成本：保持 V1 监控与账号费率单一来源。** 账号替换 Key、地址或上游分组后，下一次成功 V1 探测读取最新账号凭证；费率同步再按既有 `account rate -> group rate = account + 0.05` 保护更新价格。收益是消除旧快照导致的假监控和漏价，维护增加约 1 个 resolver 与 1 个聚焦回归测试；不再引入 V2 或第二监控面。

### P2

- **对外分发：Developer ID、DMG 与公证。** 只在需要给其他 Mac 安装时处理；可减少 Gatekeeper 摩擦，成本是 Apple 账户、证书维护和每版发布验收，本机自用没有收益。
- **支付启用时参数化授权端口。** 正式启用支付时把 dormant deployer 端口纳入唯一配置源，预计少于 1 小时；当前没有监听和调用者，不提前迁移。
- **中国站点、Turnstile、语义审核和自动切换。** 仅在合规、付费方案、真实滥用或第二 origin 到位后评估；当前新增故障域和维护成本大于收益。

## 5. 已无继续优化价值

- 不恢复闲鱼、Frist-API、CC 中转或中央生图 MCP；不再围绕已下架商品建设库存、自动发货、官方小程序或第二订单事实源。
- 不新增 Gate、证据编译器、计划 Schema、一次性测试包、常驻 AI 管理面、第二启停控制面或第三套备份工具。
- 不因版本号或告警数量强制升级 OpenClaw、Sub2API/New-API、Tauri、Wry、Tao 或 glib；只在有明确安全/稳定收益和回滚时升级。
- 不按测试文件数量继续清理。当前产品/运行源码约 320,679 行、测试约 80,476 行（约 25%）、文档约 14,285 行（约 4.5%）；项目仍偏宽，但重量主要来自真实产品域和上游镜像，已不再由闲鱼控制面或审计报告主导。
- 不删除支付、订单、授权、数据库迁移、备份恢复、安全、投资风控和关键浏览器测试；也不拆散上游镜像测试。
- 不新增硬件、付费套餐、合成负载、数据库双写、Geo DNS、Load Balancer 或中国/海外双站自动切换。

## 6. 用户事项与硬件结论

- 闲鱼没有后续用户操作：商品已全部下架、无待处理订单，助手和自动交付已经退役。
- 仅在需要时由用户处理：MFA、账户恢复、续费、付款、所有权转移、Apple Developer ID、公证、加密离机备份目录/公钥、供应商图片模型权限和任何新付费方案。
- 实体手机验收、China Network/Load Balancing、域名/ICP 和中国 origin 均未具备。Mac 与 Oracle 当前资源充足，不需要新增硬件或升级套餐。
