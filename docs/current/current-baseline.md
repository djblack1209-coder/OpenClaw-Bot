## 2. 发现并已修复的问题

- **费率同步已启用但不能修复既有漂移。** 旧逻辑只有当 group 已经正好等于“账号历史倍率 + 0.05”时才会更新；一旦有人在上游换分组或手动改过价格，它会静默跳过，导致漂移永久存在。现在受管文本 group 由唯一绑定关系决定，更新以 group 的实际当前值做 CAS，再写入账号倍率加既有 `+0.05` 合同。生产真实同步已把 1 个漂移收敛为 0。
- **缺少历史账号倍率时会提前跳过。** 运行时账号对象没有旧倍率字段时，旧代码会在读取当前 group 前返回。该字段对新的实际值 CAS 不再必要，已删除该早退条件；回归测试覆盖“已有漂移且运行时旧倍率缺失”的情形。
- **停用绑定后旧监控仍可运行。** 旧 resolver 只校验账号 active，未校验 channel/group active，因此会继续探测已停用受管绑定的旧凭证。现在三层绑定都必须 active；若受管绑定存在但已停用，监控自动禁用并取消调度。独立监控仍可使用自己的快照，不受影响。
- 2026-08-12 的 Redis 503 根因已维持修复：Cloudflare 策略写入路径统一复用最小 ACL，避免覆盖 Redis 对配置目录的遍历权限。真实 Redis 重启、连续公网健康回读和备份恢复材料均通过。
- 远端 CI 在本轮发现桌面管理器根 `nanoid` override 为 `3.3.17`，触发高危 GHSA-2v37-7h3g-55p8；已在同一主版本升级到 `3.3.18` 并重生成锁文件。前端高危审计、TypeScript、lint 和生产构建通过。
- 本轮没有新增控制面、Schema、常驻服务或一次性测试包。仅更新既有 `v0.1.173` 两个受管补丁，并向各自已有回归测试加入最小防回归案例。

## 3. 未修复问题及原因

- 两条生图上游仍分别被权限拒绝和目标模型缺失阻断。Sub2API、鉴权和 R2 路径可用；未继续制造付费探针，也不恢复中央 MCP 掩盖上游问题。
- 5 个最新上游模型结果仍为错误。它们需要供应商恢复、限流解除或在真实持续失败后由运营决定停用对应报价；本轮没有把上游故障伪装为本站正常。
- 供应商后台的监控页与 JIYU 不必、也不能逐项完全相等：请求来源、当前账号、模型和探测时间不同。JIYU 现在保证的是本站真实路由的最新状态；2026-08-13 之前的历史记录可能使用旧 Key、旧模型或旧分组，不应用来与供应商当前页做同一时刻对比。
- Huyun 没有可用的 `/monitor` 页面，不能据此自动得出本站价格或健康结论。新增渠道仍必须在 Channels、Groups、Accounts 中建立绑定，不能只填地址和 Key 绕过区域、价格与安全策略。
- App 仍是内部 ad-hoc 签名；对外分发需要 Apple Developer ID、公证材料和单独验收。Chrome 扩展管理页受浏览器安全策略限制，实体手机也未连接。
- VPS-Config 现有主机探针不检查 JIYU 公网业务，不能提供本站外部故障通知。该控制面在本项目边界外，未在本仓新建第二个 watcher。

## 4. 仍值得实施的优化

### P0

- 当前没有生产阻断。不要为了清零监控错误而改 DNS、路由、数据库、健康核心服务或恢复已退役功能。

### P1

- **稳定性：在资产侧既有外部监控加入 JIYU `/health` 与连续失败通知。** 预期把人工发现时间从小时级降到约 5 分钟；一次性约 15-30 分钟，后续维护为一条既有探针。此项跨项目，需在 VPS-Config 维护窗口执行。
- **可用性：按真实持续失败停用或修复上游报价。** 连续失败且影响用户的渠道应先停售/隐藏对应模型，再由供应商恢复后最小探针验收。收益是避免把不可用模型卖给用户；维护成本为一次运营决策和一次回读，不增加自动化。
- **生图：供应商确认恢复后做一次最低成本真图验收。** 检查异步终态、MIME、对象大小、访问期限和 R2 清理。收益是将可用能力变为可交付；成本为一次真实调用费和约 10 分钟，不保留周期探针。
- **移动端：连接实体手机后复用现有关键浏览器流程。** 收益是补齐唯一设备盲区；成本约 15-30 分钟，不新建测试包。

### P2

- **对外分发：Developer ID、DMG 与公证。** 仅在需要给其他 Mac 安装时处理；本机自用没有收益。
- **中国站点、Turnstile、语义审核和自动切换。** 只有在合规、付费方案、真实滥用或第二 origin 到位后再评估；当前会增加故障域和维护成本。
