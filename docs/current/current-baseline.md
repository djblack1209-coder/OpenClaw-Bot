- Oracle Singapore Sub2API 仍是账户、余额、订单、API 密钥和账本的唯一事实源。生产构建已升级为官方 `v0.1.173` 兼容包 `v0.1.173-jiyu.31344140382`；Sub2API、专用 Redis、Apache、更新定时器和备份定时器正常，内网、公网健康和 Responses WebSocket 均通过，发布后错误计数为 0。
- 2026-08-10 最终复验重新从生产运行态取证：四家官方 `/models` 均为 200，国内白名单仍为 2/4/8/61，倍率合同错误为 0；真实大陆出口返回 `403 REGION_MODEL_RESTRICTED`，真实境外出口返回 200，探针前后现有 Key 的用量和最后使用时间均未变化。
- DeepSeek、Kimi、SiliconFlow、智谱的 JIYU Key 已在各官方控制台重建，旧 DeepSeek/Kimi JIYU Key 已删除。新 Key 只经浏览器内存录入 Sub2API 原生账号表单，未写入终端、仓库、文档或剪贴板；临时内存已清除。
- 国内运行面新增 4 个账号、4 个 `region=cn` 分组和 4 个渠道，生产聚合回读为 18 个分组、16 个账号、16 个活动渠道。四个国内账号与唯一分组的倍率合同均为 `group = account + 0.05`。
- 四家官方 `/models` 零费用探针均返回 200。精确账号白名单为 2、4、8、61 个模型；SiliconFlow 返回的 91 个模型中，嵌入、重排、图像、音频、视频和 OCR 端点已排除，不使用通配符。
- 上游 URL 安全白名单已加入四家实际使用的官方域名，并通过服务重启、环境回读和公网健康检查。该写入使用现有完整备份、root-only 配置副本和失败自动回滚。
- 地域可信头已固定在规范域名的 HTTPS `*:443` VirtualHost；Apache 先删除客户端可控的 `X-JIYU-Country`/`CF-IPCountry`，只把 Cloudflare 的两位国家码写入内部头。2026-08-10 起中国大陆生产面临时暂停：可信 `CN` 请求在 Apache 站点入口统一返回 403，境外请求保持正常；该闸门由管理器 `cn-production pause|resume` 原子切换，失败自动恢复，国内账号、分组、渠道和模型白名单均未删除。
- 产品目标仍是“中国大陆 IP 指向中国服务器站点，其他 IP 指向海外服务器站点”，但中国 origin、域名/ICP 和路由维护窗口尚未具备，因此当前只在海外站点提供生产服务；Oracle Singapore 仍是账户、余额、订单、密钥和账本唯一事实源。后续恢复中国生产面必须在专门维护窗口执行 `cn-production resume`，并重新做双地域真实验收。
- 真实大陆与境外出口均完成 curl 和无痕 Chrome 验收。Cloudflare 分别回读 `CN` 与非 `CN`；同一现有境外分组 Key 请求原生只读账单端点时，大陆返回 `403 REGION_MODEL_RESTRICTED`、境外返回 200，验证大陆不能绕过、境外仍可使用海外分组。探针前后 Key 的 `last_used_at` 和用量均未变化，没有调用模型或产生费用。
- 新构建在共享 API Key 中间件之外，同步过滤用户“可用分组”“可用渠道”和“模型广场”，避免出现“页面看得到但调用被拒绝”的操作面。构建从固定官方 `v0.1.173` 源码应用四组 JIYU 补丁，CI、安全门、前端、Rust/GTK 编译、ARM64 产物哈希和 fresh-clone 重放均通过，并经发布前数据库备份、失败回滚链、重启和运行哈希回读上线。
- 原生 Channel Monitor V2 已启用（`channel_monitor_enabled=true`、`channel_monitor_mode=v2`、60 秒刷新）。监控调度、聚合、watermark 和指标表均来自 Sub2API v0.1.173 原生实现，不是 JIYU 自建引擎；JIYU 代码只提供设置页接线、供应商标签/排序和只读 readiness 回读。10 条旧主动监控记录保留用于回滚，但切换后不再推进；不新增会计费探针、不制造合成负载。

## 明确暂缓与原因

- GitHub 仍报告一个中等级别 Rust `glib 0.18.5` 传递依赖告警。官方最新 Tauri `v2.11.5` 的 `tauri-runtime-wry 2.11.4` 仍约束 `wry ^0.55.0`、`tao ^0.35.0`；官方最新 Wry `0.56.0` 和 Tao `0.36.0` 也仍依赖 GTK3 `0.18`。`glib 0.18.5` 已是该兼容链最高版本，升级到 `glib 0.22.8` 需要上游成套迁移 GTK4，不能以单包强升或锁文件分叉制造桌面回归。
- 官方 `v0.1.173` 已完成整体补丁移植并生产部署。原生“同步上游模型”仍不自动改写四家国内精确白名单：当前白名单是上游目录与已有定价/业务类型的交集，自动扩展会把嵌入、重排、图像、音频等非聊天模型重新带入操作面，收益不足以抵偿回归风险。
- Merlin Clash 未发现可接管的路由器运行面，本轮未修改本机代理规则；生产地域强制不依赖 Merlin Clash。
- Turnstile 按既定产品决策保持关闭。开放注册目前只以邮箱验证、源站限流和 Cloudflare 现有规则兜底，仍存在自动注册消耗邮箱额度和人工处置时间的残余风险；本轮没有擅自扩大认证操作面。

## 优化优先级

- P0：无。当前生产健康、地域强制、价格回退、倍率合同、被动监控、备份与恢复材料均已通过真实回读。
- P1：仅在供应商模型目录变化或明确要求扩容时，使用 v0.1.173 原生同步做“预览→人工确认→精确白名单”维护；收益是把一次目录核对从 30-60 分钟降到 5-10 分钟，维护成本是每次上游目录变化复核，当前无需常驻自动化。
- P1：Cloudflare 控制台登录态已验证可读；仅在取得现场验收窗口后再评估启用 Turnstile。预计可明显降低自动注册和邮件验证码消耗，但会增加挑战失败、客户端兼容和客服处理成本，未取得真实误伤数据前不直接上线。
- P2：只有供应商提供明确的免费、专用安全分类模型时，才启用异步 Prompt Audit 节点；收益是补足语义风险识别，代价是模型更新、误判复核和 Key 轮换。当前收益不足，不实施。

## 已无继续优化价值

- 不升级 New-API 只为价格同步，不安装社区价格同步管理面，不新增第二事实源、补号 App、合成压力测试、付费套餐或硬件。站点级中国/海外 IP 分流只有在中国 origin、域名/ICP 和不增加事实源的边界确定后才有实施价值；不能用现有海外模型过滤冒充站点分流。
- 不为四个国内渠道创建会计费的周期性主动探针；现有零费用目录探针、被动真实请求指标和手工故障探测已覆盖当前需求。
- 不单独强升 `glib`、`wry` 或 `tao`。官方最新 Wry/Tao 仍使用 GTK3 `0.18`，本地继续优化无法改变这条上游依赖链；只在 Tauri 官方完成 GTK4 成套迁移后复查。

## 中国/海外站点分流（当前阻塞）

- 目标架构：Cloudflare 按可信国家标记把中国大陆请求送到中国站点 origin，其他请求送到 Oracle Singapore；中国站点只做无状态网关/页面和已验证国内模型，账户、余额、订单、API 密钥、支付和账本通过受保护接口回到 Oracle，禁止复制数据库。
- 2026-08-10 已通过现有 Chrome 登录态只读核对 `245334.xyz`：区域处于 Business 套餐，当前 JIYU 代理 DNS 记录仅指向 Oracle Singapore；没有 JIYU 中国 origin 或现成的地域路由。该控制台访问消除了浏览器登录态障碍，但不改变独立中国 origin、域名/ICP、健康端点和回滚包缺失的事实。
- 低维护实现优先级：先确认 Cloudflare China Network/Geo DNS 的套餐与合规条件；若不购买 Enterprise/China Network，则只能评估单一 Cloudflare Worker 按 `request.cf.country` 代理到中国 origin，且必须增加 origin 认证、超时、回源失败保护和真实双地域验收。当前不直接新建 Worker。
- 官方门槛：Cloudflare Load Balancing 为付费附加项；China Network 需要 Enterprise、单独订阅、有效 ICP 备案/许可和 JD Cloud 内容审核。项目当前禁止升级付费套餐，且没有 JIYU 中国 origin，因此该 P0 需用户先处理前置事项。
