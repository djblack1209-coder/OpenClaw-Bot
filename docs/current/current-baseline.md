# JIYU AI 当前生产基线

> 更新时间：2026-08-10。生产运行时是唯一事实；本仓库只用于维护、恢复和异地备份。

## 已验证事实

- Oracle Singapore Sub2API 仍是账户、余额、订单、API 密钥和账本的唯一事实源。生产构建为 `v0.1.172-jiyu.31328941240`；Sub2API、专用 Redis、Apache、更新定时器和备份定时器正常，内网与公网健康检查通过，发布后 10 分钟错误计数为 0。
- DeepSeek、Kimi、SiliconFlow、智谱的 JIYU Key 已在各官方控制台重建，旧 DeepSeek/Kimi JIYU Key 已删除。新 Key 只经浏览器内存录入 Sub2API 原生账号表单，未写入终端、仓库、文档或剪贴板；临时内存已清除。
- 国内运行面新增 4 个账号、4 个 `region=cn` 分组和 4 个渠道，生产聚合回读为 18 个分组、16 个账号、16 个活动渠道。四个国内账号与唯一分组的倍率合同均为 `group = account + 0.05`。
- 四家官方 `/models` 零费用探针均返回 200。精确账号白名单为 2、4、8、61 个模型；SiliconFlow 返回的 91 个模型中，嵌入、重排、图像、音频、视频和 OCR 端点已排除，不使用通配符。
- 上游 URL 安全白名单已加入四家实际使用的官方域名，并通过服务重启、环境回读和公网健康检查。该写入使用现有完整备份、root-only 配置副本和失败自动回滚。
- 地域强制已启用。首次真实双地域探针发现地域头块被旧安装器误放在 `*:80`，导致 HTTPS 请求全部按未知来源限制；现已修复为依据现有规范域名唯一定位目标 `*:443`，自动移除旧错位块并幂等安装。生产回读为目标块 1、错位块 0；Apache 先删除客户端可控的 `X-JIYU-Country`/`CF-IPCountry`，只把 Cloudflare 的两位国家码写入内部头。
- 真实大陆与境外出口均完成 curl 和无痕 Chrome 验收。Cloudflare 分别回读 `CN` 与非 `CN`；同一现有境外分组 Key 请求原生只读账单端点时，大陆返回 `403 REGION_MODEL_RESTRICTED`、境外返回 200，验证大陆不能绕过、境外仍可使用海外分组。探针前后 Key 的 `last_used_at` 和用量均未变化，没有调用模型或产生费用。
- 新构建在共享 API Key 中间件之外，同步过滤用户“可用分组”“可用渠道”和“模型广场”，避免出现“页面看得到但调用被拒绝”的操作面。构建从固定官方 `v0.1.172` 源码应用补丁，完成前端类型检查、服务/鉴权/嵌入式前端验证，并经受限 root 代理备份、暂存、重启和运行哈希回读上线。
- 现有 10 个主动渠道监控保持不变。没有为四个国内渠道新增周期性主动探针，因为原生监控会真实调用主模型并产生费用；当前使用官方 `/models` 连通性、真实账号/渠道状态和被动业务指标，不制造合成负载。
- 官方 `model-price-repo` 回退资源已完成 SHA-256 和 JSON 校验后原子安装。价格同步只使用 `resolved_rate_multiplier`；账号倍率与唯一合格文本组的 `+0.05` 在同一事务中更新、审计和回滚，生图组、歧义关联和用户专属覆盖保持不写入。
- 内容审核保持原生“前置拦截 + 仅关键词”模式，不调用付费审核 API。精确规则从 7 条扩充为 29 条，命中记录从 180 天降为 30 天、未命中记录从 3 天降为 1 天；输入摘要继续使用 240 字符上限和凭据脱敏。
- 内容审核文本和关键词匹配已统一增加 Unicode NFKC 规范化，覆盖全角提示词注入绕过；标题、正文和可用 OCR 的结构化抽取、密钥脱敏及现有关键词短路保持不变。
- 原生 Prompt Audit 仍未启用扫描 Worker，节点数为 0。四家现有 Key 均未证明提供专用安全分类模型，因此不拿普通聊天模型冒充审核器，也不增加队列噪声或明文提示词存储。
- 管理员已由本人完成 TOTP 注册，生产回读为 TOTP 用户 1、Passkey 0；全局 TOTP 和 Passkey 能力保持开启。用户明确要求暂不启用敏感操作 step-up，因此 `step_up_enabled=false` 是当前产品决定，不是配置遗漏。
- 补号助手已接入已签名 `OpenClaw.app 0.1.1` 的“系统设置 -> 补号助手”，日常无需输入 `make`；页面只绑定 `http://127.0.0.1:18796`，`make jiyu-sub2-replenish` 仅用于排障。Computer Use 桥接已通过干净重启恢复，真实点击“打开补号助手”后 Chrome 直接打开本机页面，页面无输入也可完整读取且 HTTP 返回 200；没有解析账号或触发补号。
- 管理员完成 MFA 后已重新生成完整一致性备份，覆盖数据库转储、生产二进制、版本、环境、实际 Apache 配置、页面、品牌和价格资源，共 23 个文件；核心数据库/二进制/版本恢复材料均存在。

## 明确暂缓与原因

- GitHub 仍报告一个中等级别 Rust `glib 0.18.5` 传递依赖告警。官方最新 Tauri `v2.11.5` 的 `tauri-runtime-wry 2.11.4` 仍约束 `wry ^0.55.0`、`tao ^0.35.0`；官方最新 Wry `0.56.0` 和 Tao `0.36.0` 也仍依赖 GTK3 `0.18`。`glib 0.18.5` 已是该兼容链最高版本，升级到 `glib 0.22.8` 需要上游成套迁移 GTK4，不能以单包强升或锁文件分叉制造桌面回归。
- 官方 Sub2API 最新版为 `v0.1.173`。当前未直接升级，因为 JIYU 四组补丁和生产回滚链锁定 `v0.1.172`；`v0.1.173` 的上游模型同步预览能替代手工白名单刷新，值得在下一次明确版本收益时整体移植和回归，而不是裸二进制覆盖。
- Merlin Clash 未发现可接管的路由器运行面，本轮未修改本机代理规则；生产地域强制不依赖 Merlin Clash。

## 优化优先级

- P1：在下一次有明确上游收益时把四组 JIYU 补丁移植到 `v0.1.173` 或更新版本，并用原生上游模型同步替代手工刷新；预计把每次四家模型目录维护从 30-60 分钟降到 5-10 分钟，代价是一次完整补丁移植和生产回归。
- P2：只有供应商提供明确的免费、专用安全分类模型时，才启用异步 Prompt Audit 节点；收益是补足语义风险识别，代价是模型更新、误判复核和 Key 轮换。当前收益不足，不实施。

## 已无继续优化价值

- 不升级 New-API 只为价格同步，不安装社区价格同步管理面，不新增 Cloudflare Worker、第二事实源、补号 App、合成压力测试、付费套餐或硬件。
- 不为四个国内渠道创建会计费的周期性主动探针；现有零费用目录探针、被动真实请求指标和手工故障探测已覆盖当前需求。
- 不单独强升 `glib`、`wry` 或 `tao`。官方最新 Wry/Tao 仍使用 GTK3 `0.18`，本地继续优化无法改变这条上游依赖链；只在 Tauri 官方完成 GTK4 成套迁移后复查。
